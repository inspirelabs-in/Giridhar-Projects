Root Cause Analysis

PERF-01 219 images loaded on homepage CRITICAL
The homepage loads 219 images simultaneously. Even with lazy loading attributes present, the sheer volume overwhelms the browser's render queue. Many images appear to be brand logos, testimonial avatars, and decorative elements that could be SVGs or deferred.
Page: / (Homepage) | Impact: LCP, Speed Index, Total Blocking Time
Recommended Fix

Reduce to <50 images above-the-fold. Convert brand logos to optimized SVG sprites. Use intersection observer-based lazy loading. Implement responsive srcset for all remaining images.

PERF-02 TTFB 2.3s — Server response time 3x over threshold CRITICAL
Time to First Byte of 2.3 seconds indicates severe server-side bottleneck. The threshold is 0.8s. This suggests either: (a) poor hosting infrastructure, (b) unoptimized database queries, (c) no CDN for initial page delivery, or (d) heavy server-side rendering without caching.
Page: All pages | Impact: Every metric is affected downstream
Recommended Fix

Deploy CDN (Cloudflare/Fastly) for edge caching. Implement full-page cache for static marketing pages. Optimize database queries. Consider moving to a faster hosting tier or switching to static generation for marketing pages.

PERF-03 Heavy scroll animations block rendering MAJOR
Multiple scroll-triggered animations use JavaScript to fade/slide content into view. These animations add to main thread blocking time, delay content paint, and make content invisible to users who scroll quickly. Some animations also trigger forced layout recalculations (layout thrashing).
Page: / (Homepage) | Impact: FCP, INP, accessibility
Recommended Fix

Replace JavaScript scroll animations with CSS-only animation-timeline: scroll() or remove entirely. Content should be visible by default — use progressive enhancement for animations, not the other way around.

PERF-04 No image optimization pipeline MAJOR
Images are served in original format without WebP/AVIF conversion. No responsive srcset attributes detected. Images are not size-optimized — full-resolution images served on mobile where a 400px wide version would suffice.
Page: All | Impact: LCP, bandwidth, mobile performance
Recommended Fix

Implement automatic WebP conversion with AVIF fallback. Use <picture> element with srcset for responsive images. Compress all images to <100KB. Use image CDN (Cloudinary/imgix) for on-the-fly optimization.

7.2 Homepage Philosophy Comparison

Pure marketing landing page. Hero headline, feature bullets, testimonials, FAQ. Zero actual product content visible. User must sign up before seeing any value. Approach works for B2B SaaS landing pages, NOT for consumer affiliate platforms where deal discovery drives engagement.

Immediately shows flash deals, prices, cashback amounts, category grid, trending deals, countdown timers, and search bar. User sees value on first scroll. Marketing copy is minimal — the deals ARE the marketing. This approach converts because users can self-qualify instantly.

Pre-GTM Blockers — Must Fix Before Any Acquisition Spend

  1. Fix the broken earnings calculator — primary conversion tool is non-functional. Debug JS errors, test across browsers, add error boundary with fallback UI.
